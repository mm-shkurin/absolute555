# Настройка сервера и репозитория

То, что автоматика закрыть не может: делается один раз руками, на сервере и в настройках
GitHub. Порядок здесь — порядок безопасности, а не удобства: пока не сделан первый раздел,
автоматическое развёртывание раскладывает код на машину, к базе которой есть доступ
из интернета.

## 1. Firewall

Compose пишет правила в iptables напрямую и обходит ufw: закрытый в ufw порт остаётся
доступным. Поэтому наружу отдаётся только то, что опубликовано в compose, и это
проверяется не настройкой, а снаружи.

```bash
sudo ufw default deny incoming
sudo ufw allow 22/tcp
sudo ufw allow 80,443/tcp
sudo ufw enable

# Проверка с другой машины. Postgres и Redis обязаны молчать.
nmap -Pn -p 22,80,443,3000,5432,6379,8000,9000,9001 <адрес сервера>
```

Открытыми должны быть 22, 80/443 и 9000 (MinIO отдаёт фотографии браузеру). 5432, 6379,
9001 и 8000 — закрыты: первые три `docker-compose.yml` не публикует, бэкенд висит на
петле. Если nmap показывает иначе — на сервере лежит `docker-compose.override.yml`,
которого там быть не должно.

## 2. Пользователь и ключ развёртывания (S2)

Ключ из секрета `DEPLOY_KEY` даёт вход на сервер всякому, кто проведёт коммит в `main`.
Поэтому он ограничен по тому, что им можно сделать.

```bash
sudo adduser --disabled-password --gecos '' deploy
sudo usermod -aG docker deploy
sudo -u deploy mkdir -p /home/deploy/.ssh

# Ключ генерируется на сервере; в секрет GitHub уходит приватная половина.
sudo -u deploy ssh-keygen -t ed25519 -f /home/deploy/.ssh/gha_deploy -N ''
```

В `/home/deploy/.ssh/authorized_keys` ключ прописывается с ограничением — так он годится
только на запуск развёртывания и ни на что другое:

```
command="cd /srv/absolute555/infra && ./deploy.sh ${SSH_ORIGINAL_COMMAND##* }",no-port-forwarding,no-agent-forwarding,no-X11-forwarding,no-pty ssh-ed25519 AAAA... gha_deploy
```

Членство в группе `docker` равносильно root: демон принимает от неё запуск контейнера с
примонтированным корнем. Ограничение `command=` — единственное, что отделяет одно от
другого, поэтому проверяется отдельно:

```bash
ssh -i gha_deploy deploy@<сервер> 'cat /etc/shadow'   # обязано не сработать
```

Секреты репозитория: `DEPLOY_HOST`, `DEPLOY_USER` (`deploy`), `DEPLOY_KEY` (приватная
половина), `DEPLOY_PATH` (`/srv/absolute555`).

## 3. Защита ветки main (G5)

Ограниченный ключ бессмысленен, если в `main` пишет кто угодно: развёртывание запускает
сама ветка.

Settings → Branches → Add rule для `main`:

- запретить force-push и удаление ветки;
- требовать успешные проверки: `rules`, `backend`, `frontend`, `stack`;
- запретить прямой пуш, слияние только из `dev`.

Прогон `release` ждёт эти же проверки сам (`gate`), но ждёт он после того, как коммит уже
в `main`. Защита ветки не пускает его туда — это разные рубежи, нужны оба.

## 4. Реестр образов

Если пакеты в GHCR приватные, серверу нужен токен на чтение: GitHub → Settings →
Developer settings → PAT с правом `read:packages`. Кладётся в `infra/.env`:

```
GHCR_USER=<логин>
GHCR_TOKEN=<токен>
```

Публичным пакетам это не нужно — `deploy.sh` логинится, только если переменные заданы.

## 5. Бэкапы

```bash
sudo crontab -u deploy -e
0 3 * * * cd /srv/absolute555/infra && ./backup.sh >> /var/log/absolute-backup.log 2>&1
```

Бэкап, который ни разу не разворачивали, — это предположение о бэкапе. Раз в месяц:
взять свежий дамп, поднять из него отдельный контейнер Postgres, открыть таблицу.

## 6. Что остаётся нерешённым

Пункты, для которых нужен второй сервер или отдельная работа. Записаны, чтобы отсутствие
было видно.

**Staging (R3).** Первый запуск нового кода в живой среде — сразу прод. Лечится вторым
хостом, куда теми же скриптами разворачивается `dev`: другой `DEPLOY_PATH`, другой набор
секретов, тот же `deploy.sh`.

**Перезапуск без простоя (R4).** `docker compose up -d` останавливает бэкенд и поднимает
новый: минута-полторы пятисотых. Compose без swarm плавно перекатывать не умеет, поэтому
решение — не флаг, а изменение схемы: два экземпляра бэкенда за nginx фронтенда и
переключение по health. Половинчатые варианты хуже прямого перезапуска: они дают ложное
ощущение, что простоя нет.

**Наблюдение (R5).** `/health` проверяется один раз при развёртывании. Упавший ночью
контейнер обнаруживается утром по жалобе. Нужна внешняя проба — она должна жить не на
этом сервере, иначе молчит вместе с ним.
