# Coding Rules

Always-on architectural core. The DDD smell catalogue, code-style catalogue and
per-layer detail live in `.claude/guidelines/coding-detail.md` — read it before writing
or refactoring backend code. Frontend equivalents: `.claude/guidelines/frontend-rules.md`.
Test discipline: `.claude/guidelines/tdd-rules.md`. Recurring failure classes to review
against: `.claude/guidelines/hazard-catalogue/`.

## Deployment

- The backend runs as multiple instances (uvicorn workers plus an ARQ worker on the
  same image). Never store application state in-memory — module-level `dict`/`set`,
  mutable default arguments, singleton caches in closures, class-level mutable
  attributes. State that must be consistent across instances goes to Postgres or Redis.

## Layers

This backend is a flat FastAPI app, not the layered clean-architecture tree the upstream
framework assumes. The layer map here is the real one:

- `app/api/` — routers. HTTP in, HTTP out: parse the request, call a service, shape the
  response. No SQL, no business rules.
- `app/services/` — business logic. Owns the rules and the transaction. Talks to models,
  S3, Redis, external APIs.
- `app/models/` — SQLAlchemy models. Columns, relationships, and behaviour that belongs
  to the row itself. No service or API imports.
- `app/schemas/` — Pydantic request and response types. The wire contract.
- `app/tasks/` and `app/ml/` — ARQ jobs and the OCR/VIN pipeline they call.
- `app/permissions/` — roles, permissions, and the FastAPI dependencies that enforce them.

Dependency direction, enforced by `.claude/skills/sprint-check/probes/config.json`:

- Routers must not import `app.models` or build queries with `sqlalchemy.select/update/delete`.
  They go through a service.
- Models must not import `app.services`, `app.api` or `app.tasks`, and must not import
  `fastapi`.
- Services must not import `app.api` and must not raise `HTTPException` or set
  `status_code`. A service raises a domain error; the router translates it to a status.

The last rule is currently violated across `offer_service.py` and others. Do not add new
violations; fix the ones you touch.

## File Size

- **Hard limit: 200 lines per file.** After any creation or refactoring, verify with
  `wc -l`. Applies to every source file regardless of type — routers, services, models,
  React components, stylesheets, config files. Two exemptions: migrations generated by
  Alembic, and seed data files such as `backend/app/data/car_catalog.json` — a catalogue
  of 71 brands cannot be split into chunks of 200 lines without inventing a boundary
  that means nothing.

## Comments

- Comments earn their place by preserving what the code cannot express: rationale,
  external constraints, contracts, safety hazards. Delete comments that narrate what the
  code already says.
- A retained rationale must affect a maintainer's present decision, must not be
  recoverable from names, types, tests or version control, and must state the
  irreducible fact briefly. Implementation history and migration stories belong in
  commit messages, not in source.
