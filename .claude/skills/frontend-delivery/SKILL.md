# /frontend-delivery

Конвейер одного экрана. Не заменяет `/continue` и не отменяет истории: это то, из чего
состоит **фронтовая полоса** внутри работы над историей.

## Порядок

```
интервью ──► мокап ──► контракт ──► вёрстка ──► тесты ──► рефактор ──► учёт
   (раз       (раз      (на экран)   (на экран)  (на экран) (на экран)  (на экран)
  на историю) на surface)
```

Порядок не произвольный. Каждый шаг дешевле следующего примерно на порядок: правка в
мокапе — минуты, та же правка в компонентах — часы, та же правка после привязки к API —
день. Всё, что можно решить раньше, решается раньше.

### 1. Интервью — раз на историю

`/interview`. Собирает то, чего нет ни в коде, ни в макете: почему правило именно такое,
что считается отказом, чего в этой истории намеренно не делаем.

### 2. Мокап — раз на поверхность

Один HTML-файл на поверхность (`ProductSpecification/ui/mockups/`), токены сверху,
экраны ниже. Правила и гейт выхода:

- **Токены первыми.** Цвет, шаг сетки, типографика, радиусы — до первого экрана. Тёмная
  тема только переопределяет значения; токен, рождённый в тёмной, — дыра.
- **Обе ширины и обе темы** — гейт. Экран, проверенный только на десктопе, приедет в
  компоненты с раскладкой, которую придётся переделывать заново.
- **Мокап — авторитет дизайна, а не черновик.** Пока экран не перенесён, правка идёт в
  мокап; после переноса — в компоненты, а в мокап бэкпортится (`ui-conventions.md`).

### 3. Контракт — до вёрстки, не после

Типы провода пишутся по `ProductSpecification/api-specs/*.yaml`, **а не по тому, что
сервер отдаёт сегодня**: бэкенд пишет ту же спеку параллельно, и встречаться надо на ней.
Живёт в `shared/api/backend/`.

- Имена полей с провода не переименовываются — `milleage` остаётся `milleage`.
  Переименование прячет расхождение до первого запроса в проде.
- Чего сервер не отдаёт — то не рисуется. Пустое имя честнее выдуманного, `null` честнее
  нуля: ноль читается как «оценка ноль», а не «оценки нет».
- Каждый недостающий кусок помечается комментарием с причиной. Это единственное место,
  где видно, чего продукту не хватает от сервера.

### 4. Вёрстка — из мокапа, а не из головы

Компоненты повторяют мокап; типы вида (`*View`) выводятся из контракта одним переводчиком
на экран (`fromSaleCar.ts` и подобные). Переводчик — единственное место, где провод
превращается в то, что читает человек.

### 5. Тесты — два слоя, оба обязательны

- **Чистый слой:** переводчики, форматирование, развилки. Быстрый, в `npm test`.
- **Браузерный слой:** один сценарий на экран, в `npm run test:e2e` против `dev:mock`.

Второй слой не опционален, и вот почему. В этом проекте 96 юнит-тестов оставались
зелёными, пока половина приложения показывала пустые экраны: чистый слой не видит экрана.
Поймал это только браузерный прогон — 17 падений из 21.

### 6. Рефактор — после зелёного, до учёта

`/refactor`. Отдельным коммитом, как требует `workflow.md`. Смысл шага в том, что до
зелёного рефакторить нечем: неизвестно, что из написанного окажется дублированием, а что
единственным экземпляром.

### 7. Учёт

`progress.md` истории и `stories.md`. Шаг, который в этой сессии пропускался чаще всего, —
и таблицы начали врать в обе стороны: сделанное не отмечено, сценарии под сделанное не
написаны.

## Гейты

Проверяемые машиной, а не глазами:

| Гейт | Что ловит | Команда |
|---|---|---|
| `check-boundaries.mjs` | межфичевые импорты | `npm run lint` |
| `check-mock-parity.mjs` | заглушка отстала от клиента | `npm run lint` |
| `npm run typecheck` | расхождение типов | — |
| `npm run test:e2e` | экран не получает данных | вручную, перед коммитом полосы |

**Паритет заглушки** добавлен после того, как расхождение случилось: экраны переехали на
`/sale_car`, `/chat`, `/user/profile`, а `mockServer.ts` остался на выдуманных
`/listings`, `/chats`, `/users/me`. Гейт требует, чтобы каждый путь из `backend/paths.ts`
либо обслуживался заглушкой, либо стоял в списке исключений с объяснением.

## Чего гейтов пока нет

Названо, чтобы не выглядело сделанным:

- **Дрейф контракта.** Ничто не сверяет типы в `shared/api/backend/` с YAML. Бэкенд
  переименовал `reason` → `label` и `accept` → `accepted`, добавил `seller` — нашлось
  чтением его кода. Лечится генерацией типов из спеки в шаг сборки.
- **Расхождение мокапа и компонентов.** Правило бэкпорта есть, проверки нет.
- **Экран без ручки.** Привязанный к неготовой спеке экран выглядит как пустой, а не как
  «сервер этого ещё не умеет». Нужен отдельный вид состояния.

## Что этот конвейер даёт

Возможность идти параллельно с бэкендом, не дожидаясь его: контракт согласован раньше
обеих реализаций, заглушка держит экраны живыми, браузерный слой доказывает, что экран
действительно наполняется. Цена — дисциплина на шагах 3, 5 и 7; пропуск любого из них
возвращает молчаливые поломки, а не шумные.
