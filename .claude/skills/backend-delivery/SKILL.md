# /backend-delivery

Конвейер одной истории. Не заменяет `workflow.md`, а называет тот его кусок, который
реально исполняется в этой сессии, вместе с гейтами и ценой пропуска каждого шага.

Парная полоса — `/frontend-delivery`. Общая точка у них ровно одна: **спека в
`ProductSpecification/api-specs/`**. Обе стороны пишут её раньше своих реализаций и
встречаются на ней, а не на «том, что сервер отдаёт сегодня».

## Порядок

```
ветка ──► интервью ──► спека ──► тест-спека ──► реализация ──► тесты
                                                                 │
                          учёт ◄── рефактор ◄── коммит поведения ◄┘
                            │
                            └──► пуш ветки ──► пуш branch:dev ──► следующая ветка
```

### 0. Ветка — от `dev`, одна на историю

```
git checkout -b features/<имя> dev
```

`dev` не выкатывается локально: дерево общее со второй сессией, и `checkout dev` затрёт
её работу. Слияние — пушем `branch:dev`, локальный ref обновляется `fetch origin dev:dev`.

### 1. Интервью — раз на историю

`/interview`. Три-четыре вопроса пачкой, у каждого готовые варианты и один помечен
рекомендацией. Не диалог: решение принимается одним раундом, а внимание тратится там, где
у человека есть знание предметной области, которого нет в коде.

Из интервью обязаны выйти три вещи: что входит, что **намеренно** не входит и почему, и
решения с их основанием (`DECISION:`).

### 2. Спека — до реализации, не после

`endpoints.md` в папке истории плюс YAML в `ProductSpecification/api-specs/`. Это точка
встречи с фронтом, поэтому пишется первой и правится немедленно, если реализация от неё
отошла — в том же коммите, что и отход.

Гейт `check_contract_types.py` сверяет схемы с типами фронта. На первом же запуске он
нашёл, что блок продавца уехал в `SaleCarPatch` — то, что клиент присылает, — вместо
`SaleCar`, того, что сервер отдаёт. Такое чтением глазами не ловится.

### 3. Тест-спека — сценарии и тиры

`/test-spec`. Гherkin в шести категориях, затем тиринг:

- **Tier 1 ≤ 10** — без чего история не работает для своего пользователя.
- **Tier 1 + 2 ≤ 25** — потолок построенного.
- **Tier 3** — записан в `tests/tier3/` и **не строится**. Туда уходит то, что проверяет
  подделку, а не правило: недетерминированные замеры времени, механизм, уже проверенный
  на соседнем маршруте.

Потолки не формальность. Они заставляют назвать, что здесь главное, до того как написан
первый тест.

### 4. Реализация

Слои и лимит 200 строк — `.claude/rules/coding-rules.md`. Файл, упёршийся в лимит, режется
по границе, которая в нём уже есть, а не пополам: `listing_lifecycle` → продавец и
модератор, `chat_service` → изменение разговора и чтение о нём.

### 5. Тесты и прогон

Круг по коду:

```
bash scripts/ci-local.sh --fast tests/test_chat.py   # ~20 с
bash scripts/ci-local.sh --fast                      # ~30 с
```

Перед коммитом — полный:

```
bash scripts/ci-local.sh --backend --no-e2e          # ~2 мин
```

Быстрый круг отвечает на один вопрос — проходят ли тесты; он и говорит «тесты зелёные», а
не «можно пушить».

### 6. Коммит поведения

Вместе с `progress.md`. Сообщение объясняет **почему**, а не что: диff показывает что.

**Коммит только путями, без `git add`:**

```
git commit -m "..." -- backend ProductSpecification
```

Индекс в репозитории один на обе сессии, и `git commit` без путей забирает всё, что в нём
лежит, включая чужое. Дважды за сессию так и вышло: удаления бэкенда уехали в коммиты
фронтовой полосы с сообщениями, которые о них не говорят. Пока в индексе пусто, забирать
нечего.

### 7. Рефактор — после зелёного, отдельным коммитом

`/refactor`. Шаг, который пропускался шесть историй подряд, пока его не потребовали
вслух.

Порядок именно такой, потому что до зелёного рефакторить нечем: неизвестно, что окажется
дублированием, а что единственным экземпляром. И потому что тесты — сеть: в первый же
заход рефактор снёс импорт, который ещё был нужен трём счётчикам, и шесть тестов сказали
об этом за минуту.

После рефактора — прогон ещё раз, потом отдельный коммит `refactor:`. Нечего менять —
одна строка о том, почему нечего.

### 8. Учёт

`progress.md` истории на все `[x]`, строка в `stories.md` на 100%, найденное по дороге —
в `ProductSpecification/tasks/BACKLOG.md` с указанием, откуда взялось. Долг, не попавший
в список в ту же минуту, растворяется.

### 9. Слияние

```
git push origin features/<имя>
git push origin features/<имя>:dev
git fetch origin dev:dev
```

Порядок пуша согласуется со второй сессией: ветка общая, и вливать её, пока другая полоса
пишет свою часть, значит вливать половину.

## Гейты

Проверяемые машиной, а не глазами:

| Гейт | Что ловит | Команда |
|---|---|---|
| `check_repo_rules.py --scope back` | лимит 200 строк, запрещённые импорты между слоями | в полном прогоне |
| `check_api_contract.py` | фронт зовёт путь, которого нет в контракте | там же |
| `check_contract_types.py` | контракт и типы фронта разошлись именами полей | там же |
| `alembic downgrade -1 && upgrade head` | ревизия без работающего отката | там же |
| `pytest` | поведение | `--fast` или полный |

У каждого гейта храповик: известное записано в baseline, красным становится **новое** —
и починенное, которое забыли убрать из списка.

`--scope back` появился потому, что гейт, всегда красный по чужой причине, перестают
читать. Общий прогон по-прежнему смотрит обе полосы.

## Чего гейтов пока нет

Названо, чтобы не выглядело сделанным:

- **Пропуск рефактора.** Проверяется глазами. Машинная форма — искать в ветке коммит
  `refactor:` после последнего `feat:` перед пушем.
- **Спека отстала от кода.** Гейт сверяет спеку с фронтом, но не с реализацией: поле,
  которое отдаёт FastAPI и не объявляет YAML, находится только через фронт.
- **Живой стек целиком.** Воркер, задача распознавания и SSE-поток покрыты на 19–20%; ни
  один тест не поднимает воркер по-настоящему. Задача 5 в `tasks/BACKLOG.md`.
- **Сквозной путь через сокет.** Разрезан надвое и покрыт по частям: `TestClient` крутит
  приложение в одном потоке, и разбудить очередь сокета из потока теста нечем.

## Что этот конвейер даёт

Шесть историй за сессию при 357 зелёных тестах и одном чекпоинте на историю: человек
смотрит не шаги, а результат и цвет прогона. Цена — дисциплина на шагах 2, 7 и 8; пропуск
любого возвращает молчаливые поломки вместо шумных.
