# Режим цикла: поднять покрытие стороны до цели

```
/behavior-tests --front 90%
/behavior-tests --back 90%
```

`--front` (или `--фронт`) — только `frontend/`, `--back` (или `--бэкенд`) — только `backend/`. Число — цель по строкам.
Без числа цель 80%. Вторая сторона не читается и не правится: другая сессия может вести
её цикл на том же дереве.

## Память цикла — журнал, а не контекст

Всё, что цикл знает о прошлых итерациях, лежит в файлах, а не в разговоре. Перед каждой
итерацией читаются только они; содержимое тестов и кода прошлых итераций не держится.

```
ProductSpecification/coverage/<front|back>/
  log.md       — журнал: одна строка на событие, только добавление
  table.md     — таблица итераций и очередь областей, переписывается целиком
```

Строка журнала — сухой факт с выводом команды, без пересказа:

```
2026-09-14 12:40 | #3 | test  | selling/useDraftSync | «ушёл и вернулся» | red: expected 'document' to be 'pricing'
2026-09-14 12:44 | #3 | fix   | selling/useDraftSync | шаг брался до загрузки | green: Tests 4 passed
2026-09-14 12:47 | #3 | cover | selling/useGallery   | «фото упорядочены»     | green сразу (фиксация)
2026-09-14 12:50 | #3 | suite | front                | 241 passed, tsc 0      | lines 27.4% (+1.9)
2026-09-14 12:51 | #3 | commit| 3f2a1c0              | fix(frontend): …       |
```

Типы: `audit`, `test`, `fix`, `cover` (тест зелёный сразу — поведение зафиксировано, багa
нет), `suite`, `commit`, `skip` (область отложена — с причиной), `stop`.

## Итерация

1. **Замер.** Фронт: `cd frontend && npx vitest run --coverage` (json-summary).
   Бэкенд: `bash scripts/ci-local.sh --coverage` (`coverage.xml`, term-missing).
   Итог в журнал строкой `suite`.
2. **Очередь.** Пересчитать `table.md`: области по числу непокрытых строк, сверху самые
   крупные. Взять **одну** область — фича, а не файл.
3. **Аудит области** (шаг 0 навыка) — строка `audit`: какие поведения обслуживает
   непокрытый код, какие сценарии уже есть в спеке и тестах.
4. **Сценарии** (шаги 1–2): одно поведение пользователя — один сценарий, в спеку истории
   и дословно в тест. Сценарий ведёт через несколько слоёв сразу — хук, клиент, отказ.
5. **Тест → журнал → правка → журнал** (шаги 3–4). Красный — строка `test` с причиной,
   правка в слое причины, строка `fix`. Зелёный сразу — строка `cover`.
6. **Набор стороны зелёный** (фронт `tsc -b` + `vitest run`; бэкенд `ci-local.sh --fast`),
   замер — строка `suite` с дельтой.
7. **Коммит.** Одна область — один коммит: тесты области вместе с правками найденных в
   ней багов. `fix(...)`, если правился код, иначе `test(...)`. Только свои файлы
   (`git show --stat`). Строка `commit` с хешем. `log.md` и `table.md` — в тот же коммит.
8. Обновить `table.md`, вывести таблицу пользователю, следующая итерация.

## Уровни тестов, дающие строки

| Сторона | Код | Тест |
|---|---|---|
| фронт | `logic/` | vitest на чистых функциях |
| фронт | хуки `use*.ts` | `renderHook` + `QueryClientProvider`, `fetch` подменён ответом формы сервера |
| фронт | страницы, `shared/ui` | `render` + `userEvent`: нажал → увидел |
| фронт | `api/`, `shared/session` | реальный `send`/`authorizedRequest` поверх подменённого `fetch` |
| бэкенд | `api/` + `services/` | HTTP чёрным ящиком через `client`, строгие `==` |
| бэкенд | `tasks/`, `ml/` | вызов задачи с подменённым внешним сервисом из `conftest.py` |

Selenium-сценарии в процент vitest не попадают — для цели по строкам не пишутся.
Логику из компонента сначала выносят в `logic/` (правило тонкого компонента), потом тестируют.

Запрещено ради цифры: тест без проверки наблюдаемого результата, снапшот вместо
утверждения, исключение файлов из замера, `toBeTruthy` там, где есть точное значение.

## Таблица `table.md`

```
Цель: front 90% lines · старт 23.8% · сейчас 31.2% · итераций 4

| # | Область | Сценариев | Багов | Строк +  | Покрытие | Коммит  |
|---|---------|-----------|-------|----------|----------|---------|
| 1 | selling | 6         | 1     | +186     | 30.9%    | 3f2a1c0 |

Очередь: moderation 180 · listing 152 · profile 82 · importRequest 81 · …
Отложено: shared/ui/Map.tsx — только браузер (canvas), см. log #2
```

После каждой итерации таблица выводится в ответ целиком.

## Остановка

- цель достигнута — строка `stop: target`;
- три итерации подряд дают меньше +0.5 п.п. — `stop: plateau`, в сводке — что осталось и
  почему оно дорого (браузер, внешний сервис, мёртвый код);
- набор стороны красный и причина не в области итерации — `stop: foreign red`, не чинить
  чужое молча;
- правка требует решения продукта (смена поведения, не баг) — `skip` с вопросом, дальше.

Контекст разговора сжимается — цикл продолжается с чтения `log.md` и `table.md`.
Для работы без присмотра навык запускается через `/loop /behavior-tests --front 90%`:
каждая итерация начинает с файлов, а не с памяти.

## Итоговая сводка

По остановке — последний полный замер и прогон, затем разбор `log.md`:

1. Покрытие: старт → финиш по строкам, веткам, функциям; таблица по областям.
2. Найденные баги: строки `fix` — что было у пользователя, коммит.
3. Зафиксированное поведение: число `cover`.
4. Отложенное: строки `skip` с причинами.
5. Доказательства: цитаты `Tests N passed`, `tsc exit 0` / `ci-local.sh` и итоговый процент.
6. Что осталось до цели и чем это закрывается (e2e, вынос логики, удаление мёртвого кода).
