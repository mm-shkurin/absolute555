# /delivery-loop

Как в этом проекте устроена работа. Не методология вообще, а то, что реально исполняется
здесь и подтверждено одной сессией: шесть историй, 357 зелёных тестов, три гейта,
написанных после того, как их отсутствие обошлось дорого.

Полосы описаны отдельно: `/backend-delivery` и `/frontend-delivery`. Здесь — общее для
обеих и то, что принадлежит человеку, а не полосе.

## Роли

**Человек** держит три вещи и не держит остальные: **границы истории**, **порядок пуша**
и **решения предметной области**, которых нет ни в коде, ни в макете. Шаги внутри истории
он не смотрит — смотрит результат и цвет прогона.

**Сессия** ведёт историю от ветки до слияния сама и останавливается ровно в двух местах:
на вопросах интервью и на готовой истории.

Две сессии идут параллельно на одном дереве: одна бэкенд, другая фронтенд. Папки не
пересекаются, но репозиторий общий — отсюда правила про индекс и порядок пуша ниже.

## Цикл

```
dev ──► ветка ──► интервью ──► спека ──► тест-спека ──► реализация ──► тесты
                                  │                                      │
                     (точка встречи полос)         коммит поведения ◄─────┘
                                                          │
                                          рефактор ──► прогон ──► коммит рефактора
                                                                        │
                                                       учёт ──► пуш ветки ──► branch:dev
                                                                                  │
                                                                     следующая ветка от dev
```

Один чекпоинт на историю. Не потому что так быстрее печатать, а потому что промежуточное
решение без работающего кода нечем проверить — его можно только обсудить, а обсуждение
шести историй стоит дороже, чем шесть готовых историй.

## Правила

### Границы истории

**Связанное объединяется.** Если правило лежит на двух историях сразу, они идут одной
веткой: разрезанные, они оставляют половину правила без проверки. Так истории 7 и 8
(лента и карточка) шли вместе — правило «что видит гость» проверяемо только целиком.

**Несвязанное не притягивается.** Фильтр «с картой замеров» тянет за собой сущность
замеров с одиннадцатью панелями — это отдельная история, и параметр не принимается, пока
фильтровать нечем.

### Вопросы

Три-четыре пачкой, у каждого готовые варианты, один помечен рекомендацией. Не диалог:
решение принимается одним раундом. Человек соглашается по умолчанию и тратит внимание
там, где у него есть знание, которого нет у сессии.

Пример из этой сессии: «нейронка в большинстве случаев разбирает данные с фото верно» —
после этого пороги нечёткого сопоставления не крутили вслепую, а записали задачей на
проверку по реальным выдачам.

### Спека — точка встречи, а не отчёт

`ProductSpecification/api-specs/*.yaml` пишется **раньше обеих реализаций**. Фронт
типизирует провод по ней, а не по тому, что сервер отдаёт сегодня; бэкенд правит её в том
же коммите, в котором отошёл от неё.

Сверяется машиной: `python scripts/check_contract_types.py`.

### Найденное — в бэклог, а не в текущую ветку

Всё, что всплыло по дороге и не входит в историю, идёт строкой в
`ProductSpecification/tasks/BACKLOG.md` с указанием, откуда взялось. Ветка не разбухает,
долг не растворяется. Так туда попали покрытие бэкенда, отдельная цель для замера
покрытия и фронтовый контракт после смены формы ленты.

### Нерабочее — из репозитория, а не под комментарий

VK-авторизация требовала бизнес-аккаунта, которого нет: файлы вышли из репозитория и
попали в `.gitignore`, роутер отвязан, настройки удалены. Полупроводок хуже отсутствия —
он выглядит рабочим и отвечает 500 тому, кто его найдёт.

### Работающее берётся, а не пишется

Авторизация Яндекса перенесена из соседнего проекта, где она работает против живого
провайдера, и приспособлена к здешней архитектуре. Чужая архитектура — не повод писать
заново.

### Рефактор — шаг цикла, а не настроение

После зелёного, отдельным коммитом. До зелёного рефакторить нечем: неизвестно, что
окажется дублированием, а что единственным экземпляром. И тесты — сеть: в первый же заход
рефактор снёс импорт, нужный трём счётчикам, и шесть тестов сказали об этом за минуту.

Шаг пропускался шесть историй подряд, пока не был записан. То, что живёт только в памяти,
на седьмой истории пропадает.

### Коммит — путями, без `git add`

```
git commit -m "..." -- backend ProductSpecification
```

Индекс в репозитории один на обе сессии. `git commit` без путей забирает всё, что в
индексе, включая чужое: дважды за сессию удаления бэкенда уехали в коммиты фронтовой
полосы с сообщениями, которые об этом не говорят. Пока в индексе пусто, забирать нечего.

Новый файл, которого git ещё не знает, добавляется точечно и коммитится сразу:
`git add -- <файл> && git commit ... -- <пути>`.

### Ветки и пуш

- Ветка от `dev`, одна на историю. `dev` локально не выкатывается: дерево общее.
- Слияние — `git push origin <ветка>:dev`, затем `git fetch origin dev:dev`.
- **Порядок пуша принадлежит человеку.** Вливать ветку, пока вторая полоса пишет свою
  часть, значит вливать половину.

## Гейты

Проверяемые машиной. У каждого храповик: известное в baseline, красным становится новое —
и починенное, забытое в списке.

| Гейт | Что ловит |
|---|---|
| `check_repo_rules.py --scope back\|front` | лимит 200 строк, запрещённые импорты между слоями |
| `check_api_contract.py` | фронт зовёт путь, которого нет в контракте |
| `check_contract_types.py` | контракт и типы фронта разошлись именами полей |
| `alembic downgrade -1 && upgrade head` | ревизия без работающего отката |
| `npm run lint` (границы фич, паритет заглушки) | межфичевые импорты, отставшая заглушка |
| `npm run test:e2e` | экран не получает данных |
| `pytest` | поведение |

`--scope` появился потому, что гейт, всегда красный по чужой причине, перестают читать. И
это худшее, что может случиться с проверкой.

## Круги

```bash
bash scripts/ci-local.sh --fast [tests/...]   # ~20-30 с, только тесты бэкенда
bash scripts/ci-local.sh --backend --no-e2e   # ~2 мин, все гейты бэкендовой полосы
bash scripts/ci-local.sh --frontend           # фронтовая полоса
bash scripts/ci-local.sh                      # обе, перед слиянием в dev
```

Быстрый круг говорит «тесты зелёные», а не «можно пушить»: про правила, контракт и откат
ревизии он не спрашивал.

## Чего в цикле пока нет

Названо, чтобы не выглядело сделанным:

- **Пропуск рефактора** ловится глазами. Машинная форма — искать коммит `refactor:` после
  последнего `feat:` перед пушем.
- **Спека отстала от реализации** — гейт сверяет её с фронтом, но не с кодом сервера.
- **Живой стек целиком**: воркер, задача распознавания и SSE покрыты на 19–20%, ни один
  тест не поднимает воркер по-настоящему.
- **Дрейф мокапа и компонентов** — правило бэкпорта есть, проверки нет.

## Как это читать

Начало сессии: этот файл, затем свой конвейер — `/backend-delivery` или
`/frontend-delivery`. Вопрос «что дальше» — `ProductSpecification/stories.md` и
`progress.md` текущей истории. Вопрос «почему правило именно такое» — `interview.md` и
`decisions/` той истории, где его приняли.
