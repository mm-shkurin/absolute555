# Архитектура фронтенда

Перенесена из Textery (`../textery/frontend`). Здесь записано, что мы берём, как это
ложится на предметную область Абсолюта и что решено иначе. Стек — в `technology.md`,
дизайн-система — в `ui/ui-conventions.md`.

Причина заимствования простая: в Textery правила архитектуры не описаны, а **проверены
гейтами**. Правило в прозе держится до первого дня, когда кому-то нужен компонент из
соседней фичи — такое решение принимают не обдумывая, а глядя в другую сторону.

---

## Слои

```
app       собирает приложение: роутинг, провайдеры, навигация — видит всё
features  вертикальные срезы продукта; фича не знает о соседней фиче
shared    транспорт, сессия, кэш, токены, конфиг, домен — не видит никого
```

Импорт идёт только внутрь. Исключений нет и заводить их не надо: если двум фичам нужен
один и тот же кусок — он переезжает в `shared`, а не импортируется наискось.

Проверяется `scripts/check-boundaries.mjs` в хвосте `npm run lint`. Рядом лежит
`check-boundaries.selftest.mjs`: **гейт, который никогда не падает, ничего не проверяет.**

## Раскладка среза

Одинаковая во всех фичах, чтобы читатель не гадал, в какой он:

```
features/<срез>/
  api/         HTTP-клиенты среза, перевод wire ⇄ приложение
  components/  то, что рисуется
  hooks/       состояние и эффекты среза
  utils/       чистые помощники и копирайтинг
  __tests__/
```

Имя папки — обещание о содержимом. Папка, в которой лежит что попало, перестаёт
что-либо сообщать.

## Срезы Абсолюта

Выведены из потоков `UserFlows.md` и экранов `ui/mockups/index.html`.

| Срез | Что внутри | Экраны мокапа |
|---|---|---|
| `landing` | посадочная для гостя | `#landing` |
| `auth` | экраны входа, возврат из OAuth, ошибка входа | модалка входа, `#oauth`, `#oauthErr` |
| `catalog` | лента, фильтры, выбор марки, пустые состояния | `#feed` `#empty` `#loading` `#cold` |
| `listing` | карточка объявления, галерея, состояния гостя / продано / своё | `#listing` `#listingGuest` `#listingSold` `#listingOwner` |
| `thickness` | карта замеров: схема кузова, заполнение, распознавание | `#thickness` |
| `selling` | мастер создания объявления, OCR СТС | `#wizard` |
| `offers` | предложения по цене с обеих сторон | `#offers` |
| `chat` | список диалогов и переписка | `#chats` |
| `profile` | мой профиль, мои объявления, публичный профиль продавца, отзывы | `#profile` `#my` `#seller` |
| `importing` | под заказ: позиции, поставщики, заявки, отклики | `#import` `#importer` `#request` `#requestNew` `#supplierForm` |
| `moderation` | очередь, жалобы, заявки на роль | `#queue` `#complaints` `#roles` |

Схема кузова живёт в `thickness`, а не в `shared`, хотя её видят и `listing`, и `selling`:
это не общий примитив, а предметный компонент одной фичи. Соседи получают его через
`app`, который и существует, чтобы сшивать экраны.

## Слои HTTP

```
shared/api/httpClient            транспорт; про авторизацию не знает ничего
shared/session/authorizedRequest токен, обновление сессии, повтор запроса
shared/api/send                  httpClient + сессия + читаемый текст ошибки
features/*/api/*Api              конкретные эндпоинты, перевод wire ⇄ приложение
```

`httpClient` намеренно не знает про токены: клиент, добавляющий токен, импортировал бы
сессию, а клиент обновления сессии тогда импортировал бы клиент, который обновляет
токен — цикл, и хуже того, обновление, способное уйти в рекурсию через собственный 401.

`shared/api/endpoints.ts` — единственное место, знающее URL-пространство сервера.
Пути собираются из сегментов, а не пишутся литералом: версия `/api/v1/` — часть
опубликованного контракта в `api-specs/`, и она должна двигаться вместе с ним.
Сегменты, которые меняются, — функции, чтобы вызывающий не забыл про кодирование.

## Сессия — не фича

`shared/session`, а не `features/auth`. В Textery на этом обожглись: слой сессии лежал
внутри фичи, и всё общее тянулось за личностью вошедшего вниз — восемь записанных
исключений с одним и тем же швом. Экраны входа остаются фичей; сессия — инфраструктура,
на которой фичи стоят.

У нас это острее: ролей пять (`guest`, `user`, `importer`, `manager`, `admin`), и роль
читают почти все экраны — лента прячет действия у гостя, карточка меняет блок кнопок,
модерация вообще существует только для двух ролей. Роль живёт в `shared/session`
рядом с токенами.

## Стили

CSS Modules на компонент, значения — из токенов. Три файла, в этом порядке:

```
styles/palette.css        сырые оттенки
styles/tokens-light.css   все токены на голом :root — единственное место, где токен РОЖДАЕТСЯ
styles/tokens-dark.css    только переопределения
```

Токен, существующий только внутри `[data-theme='dark']`, — дыра: в светлой теме он
разрешается в ничто, свойство падает в initial, и это читается как баг рендера, а не
как забытый токен. Тест падает на тёмном токене без светлой пары.

Значения светлой темы уже посчитаны и лежат в `ui/ui-conventions.md` — переносить
оттуда, а не изобретать заново.

Шрифт раздаём со своего origin из `public/fonts/`. Golos Text, вариативный,
с `unicode-range` под кириллицу и латиницу отдельно, `font-display: swap`.

## Что решено иначе, чем в Textery

- **Capacitor.** У нас Android-обёртка; она берёт готовый `dist/` от Vite, конфиг
  остаётся в корне `frontend/`. На архитектуру не влияет.
- **SSE вместо поллинга.** В Textery генерация опрашивается поллингом; у нас распознавание
  СТС и толщиномера идёт по SSE (`UserFlows.md`, поток 2). Подписка живёт в
  `shared/api` рядом с транспортом, а не внутри фичи: её слушают и `selling`, и `thickness`.
- **Аналитики пока нет.** `shared/analytics` из Textery не переносим, пока никто не
  попросил считать события.
- **Редактора нет.** Tiptap и всё, что вокруг него, к нам не относится.

## Гейты CI

Переносим по мере надобности, но два — сразу, потому что без них архитектура держится
на честном слове:

- `check-boundaries.mjs` — импорт поперёк границы фичи красит сборку;
- `check-per-file-coverage.mjs` — пофайловый пол покрытия. Общий процент прячет модуль
  с нулём: в Textery `historyApi.ts` стоял на 0%, пока все вызывающие его мокали, и
  сборка была зелёной.

У каждого гейта рядом `*.selftest.mjs`. Порог покрытия — **пол под сегодняшним
измерением, а не мечта**: его работа — краснеть, когда покрытие падает. Поднимать по
мере роста; никогда не опускать, чтобы прогнать красный билд.
