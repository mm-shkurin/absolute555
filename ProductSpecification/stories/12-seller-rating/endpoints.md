# Рейтинг продавца и публичный профиль - API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| POST | /api/v1/offer/{offer_id}/review | Оставить отзыв по состоявшейся сделке |
| PATCH | /api/v1/review/{review_id} | Править свой отзыв в течение 24 часов |
| GET | /api/v1/seller/{user_id} | Публичный профиль: агрегат и число сделок |
| GET | /api/v1/seller/{user_id}/reviews | Лента отзывов о продавце, страницами |
| GET | /api/v1/seller/{user_id}/listings | Опубликованные объявления продавца, страницами |

## Notes

- **Отзыв заводится по офферу, а не по продавцу.** Путь `POST /offer/{offer_id}/review`
  и есть проверка права: у чужого оффера отзыва не бывает, у непринятого — тоже. Ручки
  «оставить отзыв о продавце X» нет намеренно, иначе рейтинг накручивается без сделки.
- **Оффер не свой — `404`.** Как и в чате: `403` подтвердил бы, что оффер существует.
- **Оффер свой, но не `accepted` — `409`.** Право появится или не появится позже; это
  состояние, а не отсутствие.
- **Повторный отзыв — `409`**, с идентификатором уже написанного, чтобы экран мог перейти
  к правке вместо второй попытки.
- **Правка — только своя и только 24 часа.** После окна — `409`; чужой отзыв — `404`.
  Удаления нет, метода `DELETE` тоже нет.
- **Агрегат в карточке и очереди — поля блока `seller`**: `rating`, `reviews_count`,
  `deals_count`. Новых вызовов ради этих трёх чисел не заводится; продавец без отзывов
  отдаёт `rating: null`, а не `0` — ноль читается как «оценили на ноль».
- **Выдача офферов добавляет два поля**: `can_review` и `review_id`. Кнопка «оставить
  отзыв» включается первым и заменяется на «изменить» вторым; без них экран угадывал бы
  право по статусу и всё равно не знал бы, писали ли отзыв.
- **Профиль публичен**: гость читает агрегат, отзывы и объявления. Телефон в профиле не
  отдаётся — он за раскрытием в карточке.
- **`/seller/{user_id}/listings` показывает только опубликованные.** Черновики и
  отклонённые — дело владельца, а не читателя профиля.
