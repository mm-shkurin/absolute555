# Автозаполнение из СТС: привязка к справочнику - API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| POST | /api/v1/sale_car/{sale_car_id}/sts | Приложить снимок СТС к черновику и запустить распознавание |
| GET | /api/v1/sale_car/{sale_car_id} | Выдача черновика получает объект `autofill` |
| PATCH | /api/v1/sale_car/{sale_car_id} | Правка `brand_id`/`model_id` объявляет поле выбором продавца |
| GET | /api/v1/sse/{sale_car_id} | Живой поток исхода — без изменений, история 4 |

Снимается: `POST /api/v1/photos/sale-car/sts`, `POST /api/v1/task/test-update`,
`GET /api/v1/task/test-page`.

## Notes

- **Загрузка СТС больше не создаёт объявление.** Прежняя ручка требовала телефон, цену и
  пробег формой, хотя фото СТС — первый шаг мастера, а цены на нём ещё нет. Черновик
  создаётся `POST /api/v1/sale_car` (история 4), снимок прикладывается к нему.
- Приложить снимок можно в `draft` и `rejected` — там же, где разрешена правка полей.
  Повторная загрузка заменяет снимок и перезапускает распознавание; прежний исход
  затирается, а поля, которые продавец уже поправил руками, остаются (см. ниже).
- **Распознанное не затирает выбор продавца.** У марки и модели есть источник:
  `ocr` — подставлено распознаванием, `seller` — выбрано человеком. Задача пишет только
  туда, где источник не `seller`. Без этого повторная загрузка СТС молча возвращает
  ошибку, которую продавец только что исправил.
- **Правка марки или модели закрывает предложение модератору** по этому написанию для
  этого объявления. Продавец, выбравший `Toyota Land Cruiser Prado` вместо распознанного
  `LC PRADO 150`, уже ответил на вопрос, который очередь собиралась задать.
- **Исход виден и после перезагрузки.** `autofill.state` в выдаче объявления повторяет
  то, что приезжает по SSE: `none` (снимка нет), `pending` (читаем), `unreadable` (фото
  не прочитали), `undecoded` (фото прочли, данные не разобрали), `done`.
  `unreadable` и `undecoded` — разные подсказки на экране: первую чинит новое фото,
  вторую — ручной ввод.
- **Ни один исход не роняет объявление.** Не разобрали — черновик остаётся, продавец
  заполняет руками.
- **`brand_id` и `model_id` перестают быть обязательными для отправки на модерацию.**
  Редкая марка не должна блокировать публикацию: объявление уходит с сырыми строками и
  просто не попадает под фильтр, пока модератор не заведёт написание (история 9).
- **Отладочные ручки статуса сносятся.** `POST /task/test-update` без авторизации писал
  статус любому чужому объявлению.
- Статусы задачи внутри `Ocr*`/`Decode*` перестают быть перепутанными: отказ модели
  на этапе чтения — `OcrFailed`, разбор ответа — `DecodeFailed`. Наружу это видно как
  `unreadable` против `undecoded`.
