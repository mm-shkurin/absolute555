# Админка: люди, роли, блокировки, сводка - API Endpoints

История заводит блокировку и журнал и меняет форму списка людей. Разделы модерации
и заявок остаются как есть — им нужен только вход с экрана, а не новый маршрут.

| Method | Path | Что делает |
|--------|------|------------|
| GET | /api/v1/role/users | Меняет форму: страница вместо всей таблицы, поиск по имени, фильтр по роли и по блокировке |
| GET | /api/v1/role/users/{user_id} | Новый: карточка человека — роль, блокировка, счётчики объявлений и жалоб |
| GET | /api/v1/role/users/{user_id}/audit | Новый: журнал действий над учётной записью. Только `admin` |
| POST | /api/v1/role/users/{user_id}/block | Новый: закрыть доступ, с причиной |
| POST | /api/v1/role/users/{user_id}/unblock | Новый: вернуть доступ, с причиной |
| PUT | /api/v1/role/users/{user_id}/role | Причина перестаёт теряться: пишется в журнал |
| GET | /api/v1/role/stats | Без изменений |
| GET | /api/v1/moderation/counts | Без изменений: числа для сводки уже считаются |

## Notes

- **Страница вместо всей таблицы.** `GET /role/users` отдавал массив всех учётных
  записей одним ответом. Форма ответа становится страницей — `items` плюс `total`, — как
  в ленте и очереди модерации. Это ломающее изменение, и оно того стоит: при плановых
  тысячах записей прежний ответ читает всю таблицу ради одного экрана.

- **`manager` видит людей, `admin` меняет роли.** Список, карточка, сводка и блокировка
  открыты обоим; смена роли и журнал — только `admin`. Продолжение правила истории 13:
  `manager` уже не выдавал роли своего уровня, здесь он не выдаёт их вовсе.

- **Блокировка закрывает вход и всю активность — `403` на любой запрос с токеном
  заблокированного.** Не `401`: токен подлинный, дело не в нём, и `401` заставил бы клиент
  обновлять исправный токен по кругу. Проверка стоит там же, где разбирается токен, а не
  в каждой пишущей ручке: ручек полтора десятка, и пропущенная — дыра, которую находит
  нарушитель.

- **Заблокированному говорят прямо.** Код ответа `USER_BLOCKED` и причина, а не общий
  отказ входа: общий отказ прячет положение дел и от нарушителя, и от задетого случайно,
  и второй возвращается снова, считая это сбоем.

- **Блокировка и разблокировка требуют причины — `422` без неё.** То же правило, что у
  отклонения объявления (история 4) и отказа по заявке (история 13).

- **Себя не блокируют — `409`.** Первый же промах иначе оставляет площадку без
  администратора, и вернуть доступ будет некому.

- **`manager` не блокирует `manager` и `admin` — `403`.** Власть над равным — тот же
  тихий путь наверх, который история 13 закрыла у заявок.

- **Повторная блокировка уже заблокированного — `409`.** Не «успех, ничего не делаю»:
  экран показал бы второе действие как состоявшееся, а в журнале его нет.

- **Объявления заблокированного уходят из ленты, но не удаляются.** Видимость — правило
  ленты (история 7), а не судьба записи; разблокировка возвращает их такими, какими они
  были.

- **Журнал пишется в той же транзакции, что и само действие.** Иначе бывает блокировка
  без записи о ней — и тогда по журналу уже нельзя судить, что происходило.

- **Журнал только читается.** Ни ручки правки, ни удаления: запись, которую можно
  подчистить, не отвечает на вопрос «кто это сделал».
