# Фото объявления: загрузка, порядок, обложка - API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| POST | /api/v1/sale_car/{sale_car_id}/photos | Загрузить снимки, multipart, до 15 в сумме |
| DELETE | /api/v1/sale_car/{sale_car_id}/photos/{photo_id} | Удалить один снимок |
| PUT | /api/v1/sale_car/{sale_car_id}/photos/order | Задать порядок целиком; первый — обложка |
| GET | /api/v1/sale_car/{sale_car_id}/sts | Подписанная ссылка на снимок СТС |

## Notes

- `DELETE /{id}/photos` со списком ключей в теле заменяется удалением одного снимка по
  пути. Пакетное удаление ничем не пользовались, а тело у DELETE половина клиентов
  отправлять не умеет.
- Выдача объявления получает `photos[]` — упорядоченный список `{photo_id, url,
  preview_url}`. `preview_photo_url` остаётся как есть: это `photos[0].preview_url`.
- Порядок присылается **целиком**, а не как перестановка двух элементов. Состав не
  совпал с тем, что лежит, — отказ целиком, без частичного применения.
- Добавление и удаление разрешены в `draft` и `rejected`. Порядок меняется в любом
  статусе: снимки уже прошли модерацию, перестановка не подсовывает новых.
- `GET /{id}/sts` отдаёт ссылку со сроком жизни, а не сам файл, и только владельцу и
  модератору. Чужому — `404`, как и на неопубликованное объявление.
- Загрузка СТС остаётся на `POST /api/v1/photos/sale-car/sts` (история 6 её перепишет);
  здесь меняется только то, куда она кладёт — закрытый бакет вместо колонки в Postgres.
